# Controle de Versão (Git e GitHub)

* **Repositório (Repository):** Espaço centralizado onde o código do projeto é armazenado e versionado.
* **Commit:** Registro de uma alteração ou conjunto de mudanças salvas no histórico do repositório.
* **Conventional Commits:** Padrão de mensagens de commit que organiza a evolução do projeto e facilita a leitura do histórico.
* **Branch (Ramificação):** Linha paralela de desenvolvimento que permite criar ou testar funcionalidades sem alterar o código principal (main/master).
* **Merge e Pull Request (PR):** Processo de solicitar revisão e integrar alterações de uma branch secundária à branch principal.
* **Git:** Sistema distribuído de controle de versão que registra alterações em arquivos e permite consultar o histórico, criar branches e integrar linhas de desenvolvimento.
* **GitHub:** Plataforma de hospedagem de repositórios Git que oferece colaboração, revisão de código, gerenciamento de tarefas e automação.
* **Clone:** Operação que cria uma cópia local de um repositório remoto, incluindo seu histórico de versões.
* **Staging Area:** Área intermediária na qual alterações são preparadas para compor o próximo commit.
* **git add:** Comando que adiciona alterações à staging area.
* **git status:** Comando que mostra o estado do repositório, incluindo arquivos modificados, não rastreados e preparados para commit.
* **Push:** Operação que envia commits locais para um repositório remoto.
* **Fetch:** Operação que busca atualizações do repositório remoto sem integrá-las automaticamente à branch local.
* **Merge Conflict (Conflito de Merge):** Situação em que o Git não consegue combinar automaticamente alterações e o desenvolvedor precisa conciliá-las.
* **.gitignore:** Arquivo que indica quais arquivos ou diretórios o Git deve ignorar.
* **Code Review:** Revisão do código por outro desenvolvedor ou membro da equipe para identificar problemas e verificar padrões do projeto.
